Fleet MRO Simulator — Closed-Loop Architecture & Build Spec

Synthetic training-data generator for AviOS predictive models

SIMULATOR — NOT A DIGITAL TWIN   Status: design spec  ·  Output target: AviOS 52-entity model

1. Purpose & Boundary (read first)

This system generates synthetic fleet histories to harden the AviOS platform end-to-end and to pre-train predictive models before fine-tuning on real operator data. It is a simulator, not a digital twin: it produces plausible, correctly-labelled data, not a physically-accurate mirror of a specific tail.

Valid for: platform/stub hardening, workflow stress-testing, model pre-training, demo data.
NOT valid for: accuracy evidence in front of buyers or investors. Synthetic accuracy proves the simulator, not the product. Real predictive validation still requires an operator's historical data — that remains the critical path.

4. Block-by-Block Spec

Config / Seed

Owns fleet size, tail types & mix, utilisation rate, sim horizon, RNG seed. Emits the run definition. Guarantees identical seed → identical run.

Fleet State Engine (core)

Owns per-component true health index, hours, cycles, time-since-check, installed part serial + life-limit remaining, open defects. Reads maintenance actions from L3; writes true health into L1 and output records to the sink. The only source of truth for what is actually happening to each tail.

Layer 1 — Telemetry

Input: true health from the Engine. Emits sensor streams where a degrading component produces drifting signals (EGT/vibration rising as health falls), plus noise. Real FDR/QAR and annotated logs blend in for realism and to anchor the synthetic distribution.

Layer 2 — Failure Models

Input: telemetry + true health. Emits failure events and the held-out true RUL / failure mode to the Label Store. Failure rates must be calibrated to real base rates and class imbalance — wide-body fleets produce very few failures per component type; over-seeding teaches a world that doesn't exist.

Layer 3 — MRO Operational Logic

Input: failure events + Layer 4 lead-times. Runs task-card procedures and a discrete-event repair queue over finite hangar bays, shift-limited techs, and parts-on-hand. Emits a maintenance action with realistic duration, including AOG waits when parts are out. MSG-3 governs scheduled vs reactive.

Layer 4 — Standards & Domain

Provides ATA chapter taxonomy (components typed the way AviOS types them), interchangeability/BOM + supply lead-times, and Part 145/43 rules. Feeds Layer 3.

Calibration / Validation

Compares the simulator's emergent failure distribution against published real base rates (e.g. SDRS). Outputs a divergence report you can later cite as "synthetic distribution matches real within X%."

5. The Tick Loop

for tick in range(horizon):            # one tick = one flight or one day
    for tail in fleet:
        state = FleetStateEngine.get(tail)
        telemetry = Layer1.emit(state.true_health, noise)
        events, truth = Layer2.evaluate(telemetry, state.true_health)
        LabelStore.write(tail, tick, truth)          # held out from model
        if events:
            action = Layer3.plan(events,
                                 parts_leadtime=Layer4.leadtime,
                                 resources=fleet_resources)   # finite
            FleetStateEngine.apply(tail, action)     # <- closes the loop
        Output.write(records_for(tail, tick))        # AviOS-keyed
    fleet_resources.advance_shift()
Calibration.compare(emergent_rates=Output, real_rates=SDRS_baseline)

7. Two Cautions to Design in From Day One

Data provenance / licensing. C-MAPSS is turbofan-degradation only (no hydraulics/avionics/airframe). Verify current licensing/terms for C-MAPSS, NGAFID and FAA SDRS before this sits under a commercial product — "public dataset" ≠ "free for commercial use."
Label integrity is the whole ballgame. The models are only as good as Layer 2's labels. Miscalibrated base rates → a confident, wrong model, which in a safety-adjacent sale is worse than no model.

This simulator strengthens the platform and pre-training. It does not shorten the critical path, which remains one operator's real historical data to move prediction precision from target to observed.
